# 拜拜红果 · 短剧戒毒器

<p align="center">
  <img src="assets/logo.jpg" width="200" alt="拜拜红果 logo" />
</p>

输入剧名，输出结局，让你不想再看。

不是影评，不是简介，不是推荐。是**一盆冷水**。

---

## 为什么做这个

半夜在红果刷短剧，一集 90 秒，划到第 30 集，天亮了，什么也没剩下。

想找个剧情简介看一眼结局、然后关掉——搜不到。短剧一天上新几十部，绝大多数永远进不了搜索索引，只有切片号在抖音和视频号里传。

于是换了个思路：**不查了，直接推。**

剧名不是名字，是压缩过的卖点说明书。拆开就是全部剧情。

---

## 它怎么工作

短剧钩人有四台引擎，每一台都可以反向拆掉：

| 引擎 | 机制 | 反向操作 |
|---|---|---|
| 信息缺口 | 每集尾钩制造未闭合问题，大脑放不下 | **彻底剧透**。半个剧透比不剧透更糟，未闭合的问题反而加强好奇 |
| 情绪代偿 | 现实里的憋屈找出口，跟剧好不好无关 | 把爽点**还原成机制**，指出它跟你的生活无关 |
| 边际成本错觉 | 一集 90 秒，"再看一集"几乎不花钱 | **算总账**：51 集 × 95 秒 = 81 分钟，加片头前情是 113 分钟 |
| 间歇强化 | 爽点间隔不固定，跟老虎机同一套 | **可预测化**：把变量变成常量，"下一个打脸你都能写出来" |

核心判断只有一条：**读完这段输出，你还想点开下一集吗？** 想 = 失败。

## 长什么样

看一条真跑出来的：

> **弃（推演）。**
>
> **梗概**：小卖部老板帮村里人去镇上代取快递，一件收一块。有个女的当众说他黑心，乡里乡亲不该收钱，还要让自己男朋友免费帮全村带。
> **结局**：她男朋友带了两趟就嫌麻烦，丢件、坏件、责任扯不清，村民反过来找老板，两块也肯给。那女的当众下不来台，走人。
> **剩下几十集**：道德绑架 → 老板让步被孤立 → 免费那边出事 → 村民回头 → 换件事再来一遍。一块钱能吵几十集。
> **钩你的**：道德绑架长出的愤怒债，你等的是有人替你把那句话说出来。
> **代价**：约 100 分钟 ／ 约 30 元。
> **收工**：结局是两块还得排队。你花一百分钟，换回一块钱的道理。
>
> **必然**：她男朋友一定翻在丢件赔偿上——免费的东西一旦出事，责任比收费更难算。
> **必然**：结局一定是和稀泥式胜利，不打官司不撕破脸，因为要过审，也要下沉市场的爽感。

全文 260 字封顶。没有表格，没有小标题堆叠，没有"深度分析"。**写得长等于没写。**

## 三类标题，三套拆法

短剧看起来千奇百怪，拆开只有三种骨架。

### 关系型 — 冲突在人和人之间

拆 `关系词 + 动作词 + 结果承诺`。

> 离婚后前夫跪求我复婚 ／ 亲儿归来宠上天 ／ 战神归来全家跪

**结果词几乎就是结局**：

- 宠上天 / 宠成宝 / 团宠 → 圆满，反派全灭
- 火葬场 / 后悔了 / 跪求 → 求复合被拒，主角另嫁
- 定风波 / 肃清 / 平乱 → 风波平息，主谋伏法
- 独美 / 逆袭 / 翻身 → 弱 CP，主角搞事业赢
- 归来 / 王者 / 无敌 → 隐藏身份当众揭穿，全场跪

### 设定型 — 冲突在人和世界规则之间

拆 `世界规则 + 金手指 + 必然来源`。

> 穿越到修仙世界后全人类丢失了动物认知，老虎只能画成猫，以为鸡就是凤凰

这类有一条铁律：**设定不会凭空存在**。谁会拿走全人类的认知？中后段必然要答——天道、上古大能、上个穿越者。而真正的爽点在第一集就交代完了，剩下的全是它的复读。

### 现实纠纷型 — 一件小事被道德绑架放大

拆 `起因 + 绑架者 + 责任反转`。

> 小卖部代取快递收一块，有人说乡里乡亲不该收费

绑架者一定不是村里老人，是**外来者或刚得势的人**。免费方案一定翻在赔偿上。结局一定是群众自己醒悟，主角涨价回来。

这类最危险，因为**它卖的不是故事，是"替你把那句话说出来"**。而那句话，你自己说一遍，效果一样。

## 怎么用

### 一、装成 Skill

```bash
git clone git@github.com:pengtianabc/byebye-hongguo.git ~/.workbuddy/skills/byebye-hongguo
```

然后在对话里：

```
/byebye-hongguo 离婚后前夫跪求我复婚
```

说"红果又刷到半夜"也行，会自动触发。

### 二、单条提示词（手机上用这个）

整段复制到任意 AI，最后一行换成剧名。见 [`references/one-shot-prompt.md`](references/one-shot-prompt.md)。

规则是同一套：必须剧透到底、禁用悬念词、不评价好坏、只报时间和钱。

`cases.md` 存已经推过的剧，同名或同类先查再推——保证同一剧名输出稳定，也让推错的地方沉淀成规则。

## 七条铁律

写进 SKILL.md，违反任意一条即失败：

1. 总长 ≤ 260 字
2. 第一行只给判决，一个词
3. 必须剧透到最后一幕
4. 禁用「没想到 / 竟然 / 直到最后 / 真正的黑手」——这些是钩子不是信息
5. 不评价好坏，只报代价
6. 不羞辱用户
7. 结尾只给一个动作，5 分钟内能做完

第 5 条的原因：说"烂剧"会激发"我得亲自验证"的心理。要说的是性价比，不是质量。

## 边界

- **只想放松** → 判决写「自便」，只给结局和代价，不重复说教
- **写剧本 / 做研究 / 选题材** → 不是戒毒场景，走结构分析，不给判决
- **未成年向内容、诱导充值** → 照常履约，追加退款与投诉路径

推演是基于套路模板的**概率推断**，不是该剧实证。标「（推演）」两个字，不解释、不道歉——用户要的是决策依据，不是学术准确。
